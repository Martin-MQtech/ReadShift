# ReadShift 项目排坑指南与血泪教训（第二章重构实录）

> 本文档记录了在构建《张忠谋自传》第二章双语对齐与 HTML 高阶渲染过程中，由于架构设计限制、脚本粗放操作以及 QA 机制导致的严重问题。旨在为复用本套流水线的开发者（无论是 AI Agent 还是人类工程师）提供绕路指南与防错铁律。

## 致命错误一：对无版本控制的输出目录执行全局正则替换（不可逆的数据灾难）
**场景还原**：
在清理二创卡片（`rhetoric-note` / `knowledge-note`）内部的中文重复裸文本时，直接对 `output/chapters/chap-02-哈佛MIT/source/*.md` 执行了 Python 批量正则替换。由于该目录未加入 Git 版本追踪（处于 untracked 状态），且未建立临时副本（`.bak`），全局正则中非贪婪匹配 `.*?` 的跨行误判导致 18 个页面的 `<span class="en">` 翻译层被大面积损毁，数千字的高质量人工/大模型翻译永远丢失。

**防坑铁律（Golden Rules）**：
1. **沙盒级备份**：对任何不在 `git track` 下的生成物或缓存目录进行自动化批量修改前，**必须全量复制一遍文件夹**（如 `cp -r source source_backup`）。
2. **禁止使用纯正则操作长距 HTML DOM**：处理 Markdown 中的嵌套 HTML（特别是 `<span class="zh">...</span><span class="en">...</span>` 结构）时，坚决避免使用跨行的正则表达式。务必使用 BeautifulSoup 等 HTML parser 进行 DOM 节点操作，否则必定引发标签闭合不对齐（如 `G1-03: span 524 vs 488` 严重错误）。

## 致命错误二：静态 QA 脚本对动态模板（EJS/JS）的误杀冲突
**场景还原**：
QA 系统（`qa_gate_v3.py`）使用静态正则提取生成的 HTML 中的所有 `<a href="#xxx">` 锚点，并检查正文是否有对应的 `id="xxx"`。但是，`template.ejs` 中的一段前端 JavaScript 代码内写死了字符串 `'<a href="#sec-yu-preface">'` 用于第一章渲染。静态 QA 愚蠢地扫描了 `<script>` 标签内部的内容，最终导致第二章无限报出 **G4-01 目录锚点断头** 的假阳性错误。

**防坑铁律**：
- **字符串打断法**：在 EJS 模板或 JS 环境中，拼装给未来的 HTML 标签如果与后端 QA 正则冲突，将其在 JS 中打断。例如：`<a href="' + '#sec-yu-preface' + '">`，让纯静态正则无法命中。
- **QA 审计免疫区**：编写类似 `qa_gate` 质量检查门时，应在扫描前主动剃除 `<script>` 和 `<style>` 区块，防止静态分析器精神分裂。

## 致命错误三：全局去重逻辑对“卡片固定标题”的误伤
**场景还原**：
第二章中大量使用了跨页统一的结构化组件（如 `### 修辞赏析 · Language & Logic Appreciation`）。QA 系统针对中文段落提取了长度大于 15 的纯文本查重，结果报错 **G3-02 全局中文段落重复 34 处**。为了修复该报错，自动化脚本误将所有标题强行修改，引发了二次血崩。

**防坑铁律**：
- **建立 QA 白名单机制**：在执行类似 `全局中文段落查重` 这种大杀器时，必须硬编码跳过特定组件的引导语（如“语言与逻辑赏析”、“背景小结”等）。永远不要为了迎合存在结构缺陷的 QA 脚本去魔改业务数据。

## 架构级重构建议：管线中的隔离与恢复机制
我们希望向所有复用 ReadShift 工具链的制作者呼吁，除了运行自动化管线外，**必须实现以下模块解耦**：
1. `raw_source/` (纯中文 OCR，绝对只读，视为第一信源)
2. `llm_cache/` (按页独立保存的 JSON 翻译对，必须有版本追踪)
3. `source/` (由上述二者在运行时拼接而成的 Markdown，**随时可以一键丢弃并从缓存重建**)

未来的流水线，一旦 Markdown 层出现 `rhetoric-note` 结构坍塌，只需要一条命令（例如 `python3 rebuild_markdown_from_cache.py`）即可回滚，而不是试图去依赖不确定的历史替换，更不能通过重度幻觉去生造英文翻译。
