# ReadShift 经验库

本文件只记录历史问题及预防办法，不包含现行执行命令。现行规则以根目录 `执行手册.md` 和 `project.json` 为准。

## 1. QA 检查了错误产物

- 症状：QA 显示全绿，但实际章节 HTML 仍有重复、断链或交互错误。
- 根因：旧 QA 固定检查 `output/preview_book.html`，没有检查刚生成的章节文件。
- 修复：QA 必须从 `project.json` 获取目标，或显式接收 `--chapter` / `--html`。
- 预防测试：坏样本必须失败；报告必须打印被检查文件的绝对路径和哈希。

## 2. 修辞赏析重复中文

- 症状：卡片中同一段中文出现两次。
- 根因：源文件同时保留裸中文和 `.rhetoric-note .zh`，渲染器又把两者都输出。
- 修复：二创内容只保留结构化 `.zh/.en`，不保留同文裸段。
- 预防测试：逐 `.rebook-card` 比较直接文本与 `.zh` 可见文本。

## 3. 修辞英文在渲染后消失

- 症状：源文件有英文，最终 HTML 只剩中文，外层 span 未闭合。
- 根因：正则在内层 `.zh` 的第一个 `</span>` 就停止。
- 修复：完整保留外层节点，并使用 `@@RNOTE0@@` 这类安全占位符。
- 预防测试：多个正常 note 必须通过；开闭标签、`.zh/.en` 数量必须成对。

## 4. 连续英文翻译块

- 症状：两个英文段落连续出现，中间没有对应中文。
- 根因：长中文拆分后，英文仍拆成两个块，或跨页合并未按语义重配对。
- 修复：以语义段为单位重建“一段中文 + 一段英文”。
- 预防测试：QA 按可见 DOM 流检查连续翻译块，不按源码行数猜测。

## 5. 正则解析嵌套 HTML 误报

- 症状：正常 note 被认为延伸到文档末尾；script 中的标签字符串被算作 DOM。
- 根因：用正则或字符串 split 解析嵌套 HTML。
- 修复：使用 HTML parser 建树，并排除 script/style/svg 内容。
- 预防测试：script 字符串含 `<span>` 不得影响计数。

## 6. `source` 与 `output/full` 双写分叉

- 症状：同一页在两个目录内容不同，复制操作会覆盖较新的人工修复。
- 根因：人工源与渲染缓存都被当成可编辑主源。
- 修复：`output/chapters/chap-*/source` 是唯一人工编辑源；`output/full` 仅作兼容缓存。
- 预防测试：渲染器直接读取 manifest 指定的章节 source；禁止手工回写缓存。

## 7. 目录标题硬编码为第一章

- 症状：第二章目录显示第一章标题。
- 根因：模板脚本写死中英文章名。
- 修复：章名、章号、序言能力、小节列表全部由 `project.json` 注入。
- 预防测试：分别构建第一、二章并检查目录标题与目标章节一致。

## 8. 事件监听跨作用域

- 症状：点击目录无反应，控制台出现 `ReferenceError`，页面可能锁滚动。
- 根因：第二个 IIFE 引用了第一个 IIFE 内部的 `nav/openNav/closeNav`。
- 修复：目录只保留一个控制器和一个监听入口。
- 预防测试：浏览器逐项验证展开、再次点击收起、遮罩关闭、条目跳转、Esc 关闭。

## 9. 重复交付文件

- 症状：纯中文文件名与 `chapter-0X.html` 内容相同，用户无法判断哪个是正式版。
- 根因：旧脚本复制兼容副本，手册继续沿用旧命名。
- 修复：每章只保留 `project.json` 声明的一份中英双语文件名。
- 预防测试：QA 检查工作区内是否出现未声明的交付副本。

## 10. 假标题与孤立短行

- 症状：正文首句、排比句或 OCR 断行被包装成小节标题。
- 根因：仅凭字符长度推断标题。
- 修复：必须回查原书文本层和版面；跨页断句按语义合并。
- 预防测试：所有新增标题记录原书页码，小节基线由高级模型验收。

## 11. 非法范围静默退化

- 症状：`RANGE`、倒序范围或无匹配文件时仍生成看似正常的 HTML。
- 根因：渲染器参数解析失败后默认全量或空量继续执行。
- 修复：非法格式、跨章范围、零文件全部非零退出。
- 预防测试：CLI 错误参数回归测试。

## 12. 明文密钥进入工作脚本

- 症状：API key 直接写在 Python 文件中。
- 根因：临时调试配置被保留为生产默认值。
- 修复：只从环境变量或安全配置读取，缺失时拒绝请求。
- 预防测试：提交前扫描 `sk-`、Bearer、token 等秘密模式；暴露的密钥必须在供应商后台轮换。

## 13. 抽屉目录缺小节但 QA 未截图式捕获

- 症状：点击左上角 `目录`，抽屉面板只有章节大标题，却看不到该章的任何小节条目。
- 根因：抽屉目录是由 `<script>` 内的 JS 在运行时根据 `toc_json` 动态构建的；若渲染器的小节收集分支（`##` → `sub-*` 锚点）未生效，则 `var subsections = []` 注入为空，抽屉自然没有任何小节项；而旧 QA 只统计静态 `<h3 class="subsection-title">`，一旦该 H3 也被吞掉就无法拦截。
- 修复：
  - 渲染器必须让 `##` H2 小节标题走独立收集分支，登记 `sub-*` 锚点并注入 `toc_json`；单章模式下抽屉用 `items = subsections` 渲染全部小节。
  - QA 新增 `[G4-02] 目录小节条目完整性`：从 `var subsections = ([...])` 提取并断言小节节点数 ≥ 1，为 0 直接 FAIL 阻断出货。
- 预防测试：分别构建拥有 0 个与多个小节标题的章节；坏样本（空 `[]`）必须 FAIL，好样本必须列出全部小节。
